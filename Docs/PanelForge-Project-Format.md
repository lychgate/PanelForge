# PanelForge — Project Folder Format (S1.1)

The on-disk layout of a PanelForge project, per spec §7.1/§7.2 and the approved
D5 resolution (owner, 2026-11-05). Implementation: `src/core/project/service.ts`
(`createProject`, `identifyProject`, `resolveProjectPath`).

## Layout

```text
MyComic/
├── project.json            ← version marker + minimal manifest (NOT the master)
├── database/
│   └── project.db          ← authoritative operational store (S1.2)
├── manuscripts/original/   manuscripts/processed/
├── characters/             locations/    objects/    styles/
├── storyboards/            artwork/generated/  artwork/approved/
├── layouts/                exports/      workflows/
└── backups/                logs/
```

The exact structure may evolve, but the project must remain understandable and portable.

## `project.json` — version marker + minimal manifest

Written atomically (tmp + rename, `0600`) by `createProject()`:

```json
{
  "formatVersion": 1,
  "projectId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "createdAt": "2026-11-05T14:00:00.000Z"
}
```

- `formatVersion` — integer format version (`PROJECT_FORMAT_VERSION`, currently `1`).
- `projectId` — UUID (`crypto.randomUUID()`), stable for the project's life.
- `createdAt` — ISO timestamp.

It is sufficient to **identify** and **version-check** a project without opening
the database: `identifyProject()` returns `NOT_A_PROJECT` (missing dir/marker),
`CORRUPT_MARKER` (unparsable or unexpected fields), `UNSUPPORTED_VERSION`
(format newer than supported — upgrade PanelForge), or the metadata.

## Canonical store (D5, approved)

- `database/project.db` (SQLite) is authoritative for operational state (S1.2).
- `project.json` is only the bootstrap manifest above — thin by design.
- JSON files inside the project (`characters/*/profile.json`, etc.) are optional
  human-readable mirrors regenerated by Core Engine export; if a mirror and the
  database disagree, **the database wins** and the mirror is regenerated.

## Paths

Stored paths are relative to the project root with `/` separators (D7) — never
absolute. `resolveProjectPath()` resolves them against the root at the
filesystem boundary and rejects absolute paths and `../` escapes.
External asset references remain an explicit, authorized exception (S1.4).
